# 终端体验与资源验收

必须在 release 构建测量。开发服务器、Rust 编译器、Node.js 开发工具不计入成品占用。

## 功能与交互

- 创建两个不同目录的终端，在 A 中启动持续输出任务，切到 B 执行其他命令；切回 A 确认任务与输出持续。
- Shell 提示符、别名、PATH、环境变量、Tab 补全、历史搜索与系统终端一致。
- 中文/英文输入法组合输入、候选词、中文宽度、emoji、选中复制、多行粘贴。
- Ctrl+C 中断 `sleep` 后 Shell 可继续输入；Ctrl+D 正常退出。
- 运行 vim / less / top，验证备用屏幕、方向键、鼠标与调整大小；测试自己使用的 AI CLI。
- Windows 分别验证 PowerShell 7、Windows PowerShell、cmd、WSL。
- 关闭终端、关闭应用时确认运行任务会结束；下次启动仅恢复定义，不冒充恢复任务。
- CLI：创建、list、唯一名称/ID 前缀、歧义报错、标签/分组、send 默认不提交、close。

## 资源测量

分别测量 0 / 1 / 10 / 30 个终端，每组记录应用及 WebView 的进程占用、Shell 和任务占用、窗口尺寸与历史行数。

| 场景 | 观察点 |
|---|---|
| 全部终端空闲 | 应用与 WebView 的 CPU、总内存；不能只统计 Rust 主进程 |
| 1 个后台终端大量输出 | 前台键盘响应、后台进度、内存是否稳定 |
| 多个后台终端输出 | 线程数、切换响应、背压能否限制输出队列 |
| 输出超过历史行数 | 滚动缓冲到达上限后内存不应持续线性增长 |
| 连续新建/关闭 | 文件描述符、线程、进程是否释放 |

macOS 可在“活动监视器”按进程层级观察应用及 `com.apple.WebKit.*` 子进程，Shell/AI 进程单独列出。Windows 使用任务管理器 / Process Explorer，Linux 使用 ps / top / smem。

不能用安装包大小替代内存数据。系统 WebView 的共享内存、缓存和 GPU 内存口径不同，跨平台比较时说明口径。尚未测试的平台与项目必须标记为待验证。
