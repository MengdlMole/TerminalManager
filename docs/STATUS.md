## 性能

原始数据见 `performance-macos.json`。release 构建，统计 Rust 主进程和此次启动新增的 WebKit XPC 进程 RSS；Shell 单列。不包含 Node 开发服务器或编译工具。RSS 求和可能重复统计共享页，不能等同于私有物理内存；CPU 是稳定 1 秒后、2 秒时间差的短样本。

最终回归采样得到空应用约 169 MiB，10 终端约 274 MiB，30 终端约 307 MiB（Shell 另约 59 MiB）；10 / 30 终端 CPU 短样本约 1% / 2.9%。较早一次回归的对应 CPU 样本为 0%，说明短采样存在波动，不能据此承诺长期空闲为零。1 终端样本已执行高输出测试，因此不是冷启动单终端基线。

关闭全部终端后 RSS 没有立即回到初始值（当次约 325 MiB）；不能据此宣称已达到极低内存或证明无长期泄漏。WebView 缓存、内存分配器与垃圾回收的影响需要更长时间测试。最终数字以 JSON 为准。

当前的性能措施主要控制后台重绘、队列和历史缓冲，并没有消除系统 WebView 的固定开销。如果需要明显低于这个内存区间，应进一步评估原生渲染后端，而不是仅凭安装包较小宣称轻量。
